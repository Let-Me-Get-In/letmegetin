# Landing — letmegetin.org

Scope: public landing at the apex `/`, mode **Persuade**. Audience: people with disabilities, relatives and carers; developers and partners second. Job: understand in one viewport that LetMeGetIn answers "can I get in?" with a structured record, then search or open the app. Proof: 634,931 places, typed criteria, open sources, public API and source code. Action: search (primary), open the app / read the API (secondary). Constraints: fr/en, WCAG 2.2 AA, no invented traction, no stock photography.

Chosen direction: the record-first hero, the first composition of the three comps. Memorable moment: the real accessibility record sits next to the headline before any search, so the product's promise is visible before it is explained.

## Direction contract

THESIS: Answer "can I get in?" with a real record in the first viewport, refusing the generic hero-plus-three-feature-cards landing.

OWN-WORLD: warm paper #f7f4ec, deep ink #18211c, one green #1f6f4a, Literata display, hairline rules, flat panels, one soft offset card shadow.

STORY: The visitor sees a legible accessibility record, understands that criteria beat a vague rating, then searches or opens a place; developers discover the open API.

FIRST VIEWPORT: Split hero at desktop. Left: oversized H1 "Savoir si on peut entrer. Avant de partir.", short intro, search field with green Chercher, trust line. Right: a tall place-record card with a green Accessible pill, twelve criteria and checked rows. On mobile the same order stacks, search before card.

FORM: Record-first hero, position 1 of the three comps, seed:a9bb32894d62c5db.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
