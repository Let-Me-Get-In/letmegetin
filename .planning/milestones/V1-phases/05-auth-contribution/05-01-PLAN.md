# Phase 5 Plan — Auth & Contribution

**Ticket:** LET-10 · **Requirements:** AUTH-01/02/03, CONTRIB-01/02, REV-02
**Depends on:** Phase 4 (reviews, `place_accessibility` writer, `filled_rate`).

## Task 1 — Accounts and tokens

**Files**
- `src/letmegetin/core/security.py` (new): scrypt hashing, HS256 JWT encode/decode.
- `src/letmegetin/config.py`: `jwt_secret`, `access_token_ttl`, `refresh_token_ttl`.
- `src/letmegetin/domain/accounts/entities.py`, `repositories.py` (new).
- `src/letmegetin/infrastructure/persistence/models.py`: `UserModel`.
- `migrations/versions/0005_auth_contribution.py` (new).
- `src/letmegetin/application/accounts/` (new): `register.py`, `login.py`, `refresh.py`.
- `src/letmegetin/api/v1/auth.py` (new) + `api/schemas/auth.py` + `api/deps.py`.

**Steps**
1. `hash_password` (scrypt, per-password salt) and `verify_password` (constant-time).
2. `create_token(user, kind, ttl)` / `decode_token(token, kind)`; reject bad signature, expired,
   wrong `typ`.
3. Register: normalize email (lowercase/strip), reject duplicates (`EmailAlreadyUsed`), min 8-char
   password, `role="user"`, optional `display_name`.
4. Login: 401 on unknown email or wrong password (same message).
5. `/refresh`: verify `typ=refresh`, issue a new pair.
6. `get_current_user` bearer dependency; `require_admin` → 403.

**Verify:** unit tests for hash/token edge cases and register/login; integration register → login →
me → refresh.

## Task 2 — Contribution

**Files**
- `src/letmegetin/domain/places/entities.py`: `Contribution`.
- `src/letmegetin/domain/places/repositories.py` + infra: `add_contribution`, `upsert_accessibility`
  (existing).
- `src/letmegetin/application/places/contribute.py` (new).
- `src/letmegetin/api/v1/places.py` + schemas: `PUT /places/{slug}/accessibility/{criterion_slug}`.

**Steps**
1. Auth required; 404 unknown place; 404 unknown criterion.
2. Upsert `place_accessibility` with `{"value": ..., "source": "user", "user_id": ...}` and append
   a `contribution` row (same value).
3. Response: criterion, value, recomputed `filled_rate` (re-read via `get_place`), 200.
4. Commit once in the endpoint.

**Verify:** integration — the value changes, one contribution row per call, `filled_rate` moves;
anonymous → 401.

## Task 3 — Review creation and admin moderation

**Files**
- `migrations/versions/0005_auth_contribution.py`: `review.user_id` nullable FK.
- `PlaceRepository.add_review(...)`, `set_review_status(...)`.
- `POST /places/{slug}/reviews` (auth) and `PATCH /reviews/{id}` (admin) + schemas.

**Steps**
1. Create: rating 1–5 (schema `ge=1, le=5`), body optional, `author_name = display_name`, status
   `published`; 404 unknown place; 401 anonymous.
2. Moderation: admin only (`require_admin`), status `published|hidden`, 404 unknown review.
3. Hidden reviews disappear from the list/rating (already enforced on read).

**Verify:** integration — create appears in the paginated list and moves the average; a normal user
gets 403 on PATCH, an admin hides it and the average/list change.

## Done when

1. Register → login → refresh → `/me` all work; duplicates and bad credentials are rejected.
2. An authenticated contribution updates the record, logs one row, and returns the new rate.
3. An authenticated review is created and visible; an admin can hide it.
4. Lint, types, security scan and the full suite pass; migration `0005` applies cleanly.
