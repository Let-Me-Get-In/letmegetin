# Phase 6 Plan — Next.js Frontend

**Ticket:** LET-11 · **Requirements:** FRONT-01..04
**Depends on:** Phase 5 merged (auth, contribution, reviews) and the running API.

## Task 1 — Scaffold, design tokens, API client and session

**Files**
- `web/` — Next.js App Router, TS strict, Tailwind, MapLibre.
- `web/src/lib/api.ts` — typed client (`fetch` wrapper, error shape, 401 → refresh once).
- `web/src/app/api/[...path]/route.ts` — BFF proxy to `NEXT_PUBLIC_API_URL`; sets/clears the
  refresh cookie.
- `web/src/lib/session.tsx` — React context: user, access token in memory, `login/logout/refresh`.
- `web/src/styles/tokens.css` — colors, spacing, type ramp, focus ring; light/dark.
- `.github/workflows/ci.yml` — add the `web` job.

**Steps**
1. `npm create next-app` equivalent by hand (no wizard noise), `strict: true`, path alias `@/`.
2. BFF: forward method/body/headers; strip hop-by-hop; relay status; cookie flags
   `httpOnly`, `secure` in prod, `sameSite=lax`, path `/`.
3. API client: one place for base URL, JSON parsing, `ApiError {status, detail}`; on 401 try
   `/auth/refresh` once, replay the request, else clear the session.
4. Tokens: access in memory only; refresh cookie handled by the BFF; never log tokens.
5. Tokens page: `app/layout.tsx` with skip link, header, footer; `lang="fr"`.

**Verify:** `npm run lint && npm run typecheck && npm run build`; a unit test for the 401-retry
and for the cookie parsing (no browser).

## Task 2 — Search: map, list and filters (FRONT-01)

**Files**
- `web/src/app/page.tsx` — server shell + `<SearchView />`.
- `web/src/components/search/MapView.tsx` (client, MapLibre), `PlaceList.tsx`, `Filters.tsx`.
- `web/src/lib/search.ts` — query state ↔ URL (`?lat&lng&radius&q&family&filters`).

**Steps**
1. URL is the source of truth; back/forward restores the search.
2. Filters: text, radius (500 m → 50 km), family (4), criteria (from the category grid or a
   compact list of the base criteria).
3. Map: OSM raster style, marker per hit, hover/selection sync with the list, "search this area"
   after a pan; geolocation button with a permission-denied fallback.
4. Empty/loading/error states; skeleton list; "no result" with a radius hint.
5. Accessibility: the list is keyboard-navigable; the map has a text alternative and does not trap
   focus; all controls labelled.

**Verify:** unit tests for `search.ts` (URL round-trip) and `Filters` (query params); `npm run
build`; manual check with the seeded places.

## Task 3 — Place record (FRONT-02)

**Files**
- `web/src/app/places/[slug]/page.tsx`
- `web/src/components/record/AccessibilityTree.tsx`, `ReviewList.tsx`, `PhotoGallery.tsx`.
- `web/src/app/places/[slug]/loading.tsx`, `not-found.tsx`.

**Steps**
1. Render `tree` recursively: groups → criteria → options; show each `value`; unknown/empty is
   "non renseigné", never a false "non".
2. `filled_rate` as a progress bar with a text value; per-family scores with labels.
3. Reviews: paginated list (page/size), average and count, empty state.
4. Photos: responsive grid with credit/license; `next/image` or plain `<img>` with dimensions.
5. Metadata (`generateMetadata`), Open Graph, canonical URL; 404 for an unknown slug.
6. Accessibility: each criterion is a definition list; the tree is navigable by headings.

**Verify:** component tests with a fixture record (tree, values, reviews); `npm run build`;
manual check of a real seeded place.

## Task 4 — Account and writes (FRONT-03/04)

**Files**
- `web/src/app/(auth)/login/page.tsx`, `register/page.tsx`, `verify/page.tsx`.
- `web/src/app/account/page.tsx` — profile + email verification status + logout.
- `web/src/components/record/ContributionForm.tsx`, `ReviewForm.tsx`.
- `web/src/components/auth/RequireAuth.tsx`, `VerifyBanner.tsx`.

**Steps**
1. Register → login → verification banner → `/auth/verify-email` via the link.
2. `RequireAuth` redirects to `/login?next=…`; after login, return to the record.
3. Contribution: one criterion at a time (select value/option/precision), `PUT` then re-fetch the
   record; show the new `filled_rate`.
4. Review: rating 1–5 + text, `POST`, then re-fetch the list; disable while submitting.
5. Handle 401 (refresh/redirect), 403 (verify email), 404, 422 with human messages.
6. Logout revokes the refresh token and clears the cookie.

**Verify:** unit tests for `RequireAuth` (redirect) and the forms (payload, disabled state);
`npm run build`; manual flow register → verify → contribute → review → logout.

## Task 5 — Quality gate and CI

**Steps**
1. `npm run lint`, `npm run typecheck`, `npm test -- --run`, `npm run build` all green.
2. CI `web` job with `npm ci`, the four commands, `actions/setup-node` pinned by SHA.
3. Lighthouse/axe pass on home and a record (manual, documented in the PR).
4. Update `AGENTS.md` commands if the scripts differ.

**Verify:** CI 6/6 + the new `web` job; no console errors; keyboard-only pass on search and record.

## Done when

1. A visitor searches by text/proximity/family, sees the map and list in sync.
2. A place record shows the tree, values, `filled_rate`, reviews and photos.
3. A user registers, verifies the email, contributes, posts a review and logs out.
4. WCAG 2.1 AA pass on the two main pages; CI includes the frontend checks.
