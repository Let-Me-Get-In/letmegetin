small dedicated class next to the other `SqlAlchemy*` repositories) exposing
`by_category_country() -> list[CoverageRow]` with one aggregate query:
`SELECT COALESCE(c.slug, '(unresolved)') AS category, p.country_code, count(DISTINCT p.id) AS
places, count(DISTINCT pa.place_id) AS with_accessibility FROM place p LEFT JOIN categories c ON
c.id = p.category_id LEFT JOIN place_accessibility pa ON pa.place_id = p.id WHERE
p.canonical_id IS NULL GROUP BY 1, 2 ORDER BY 1, 2`. Canonical rows are excluded so a merge does
not double-count; unresolved categories are named, not dropped.

- `CoverageRow` dataclass (`category`, `country`, `places`, `with_accessibility`, `fill_rate`).

  round(with_accessibility / places, 3)` (0.0 when places is 0) plus a `totals` row.
- `coverage_csv(rows) -> str` with header `category,country,places,with_accessibility,fill_rate`;
  quote via the `csv` module, never string concatenation.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI → place data | merge/reject mutate place state; there is no HTTP surface and no auth in front of the CLI (host shell access is the boundary) |
| database → CSV export | the export leaves the system and may be shared with partners |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Tampering | `merge_duplicate` | high | mitigate | Soft merge only: `canonical_id` + alias + `place_merge_log` + decision row; no UPDATE of the merged row's data and no DELETE, so clearing `canonical_id` restores the previous state |
| T-09-02 | Repudiation | `place_review_decision` | medium | mitigate | Every merge and rejection writes an immutable row with `actor` and `created`; `place_merge_log` alone would have left rejections untraceable |
| T-09-03 | Tampering | CLI actor field | medium | accept | `actor` is a constant `operator` string, not authenticated; the CLI runs under host access control and adding auth is out of scope for this phase |
| T-09-04 | Denial of service | `duplicates list` full scan | low | mitigate | `LIMIT` default 50 plus an index on `place.duplicate_of_id`; the query stays a single indexed read as the table grows |
| T-09-05 | Information disclosure | coverage CSV | low | accept | Aggregated counts only (category slug, ISO country, integers) — no user, review or contact data |
| T-09-SC | Tampering | package installs | high | mitigate | No new dependency: stdlib `csv` + SQLAlchemy aggregates |
</threat_model>
