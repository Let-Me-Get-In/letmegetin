## Accomplishments

- `GET /api/v1/places?category=<slug>` now narrows results to one category; the request without the parameter runs the exact same query as before (the predicate is guarded by `category_id is not None`).
- An unknown slug returns `422 {"detail": "unknown category"}`, the same status an unknown `family` produces, instead of a silently empty `200`.
- The web search page carries the selected category in `SearchState`, the URL and `placesPath`, so picking "Pharmacie" narrows the map and the list rather than only reloading the criterion tree.
- `docs/openapi.json` regenerated by the export script: exactly one addition (the `category` parameter), byte-stable under a second export.

## Decisions Made

- Slug resolution in the endpoint, id in the port: the domain stays unaware of Overture's vocabulary, and the ORM is never imported by `api/` or `application/`.
- Filter on the indexed FK, not the joined slug, so the existing `outerjoin` keeps serving only the response projection.
- `search-view.tsx` derives the selected category from `draft.category` rather than a second `useState`, so the selection survives reload and URL round-trip.
