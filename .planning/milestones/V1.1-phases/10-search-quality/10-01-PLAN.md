<objective>
Add a category filter to the public place search, end to end: HTTP parameter → use case →
repository port → PostGIS query → web client → committed OpenAPI snapshot (SEARCH-02,
ticket LET-34).

**Phase goal (ROADMAP):** "Search narrows correctly and scales past the MVP limit."

Planner note on MVP framing: ROADMAP's Goal line is not in user-story form, and MVP mode
requires the story to be sourced rather than authored. No `As a / I want / so that` framing is
invented here. If the story form is wanted, run `/gsd-mvp-phase 10` and re-plan.

Purpose: the search endpoint cannot filter by category today — `web/src/components/search/`
keeps the chosen category in local React state and uses it only to fetch
`/api/v1/categories/{slug}/criteria`. There is no `category` query parameter on
`GET /api/v1/places`, no category predicate in `SqlAlchemyPlaceRepository.list_near`, and no
category field in `SearchState`. A user who picks "Pharmacie" still gets every category in the
radius back.

This plan is the phase's tracer: it is the thinnest change that crosses every layer this phase
will touch (query param, use case, port, SQL, integration test against real PostGIS, contract
snapshot, web client). It is deliberately narrow — one filter, one path — and it is written for
keeps: the `category_id` plumbing it establishes is the same plumbing plans 10-02 and 10-03
extend.

Output: `category` query parameter, port + predicate, a new contract snapshot, the web client
wiring, integration tests.
</objective>

Measured facts this plan relies on (verified on the dev database, not assumed):
- `SqlAlchemyPlaceRepository.list_near` already `outerjoin`s `CategoryModel` on
  `PlaceModel.category_id == CategoryModel.id` to return the slug, so the response shape needs
  no change.
- `categories` is a flat table of 158 Overture slugs (`data/referential/categories.json`, every
  `parent_id` null), so a category filter is an exact match and needs no recursive walk.
- `place.category_id` carries `index=True` (`ix_place_category_id`), and `place.location` has
  the GiST index `ix_place_location`.

Existing patterns to copy: `family` as an enum-typed `Query` that makes FastAPI reject unknown
values with 422; `_criterion_ids` as the single place a raw query string is parsed.

  <action>
Thread one new optional filter, the category, through every layer. No other filter changes here.

Port (`domain/places/repositories.py`): add `category_id: int | None = None` as a keyword-only
parameter to `list_near`, after `family`, and extend the docstring to say it narrows to one
resolved category. Pass an id, not a slug: the domain does not know Overture's vocabulary and
the API already resolves slugs.

Infrastructure (`SqlAlchemyPlaceRepository.list_near`): when `category_id` is not None, add one
predicate, `PlaceModel.category_id == category_id`. Put it in the same conditional-chain style
as the existing `q` / `criterion_ids` / `family` blocks — do not touch the select list, the
`outerjoin`, the `canonical_id IS NULL` guard or the radius predicate. Filtering on the FK
column (indexed) rather than on `CategoryModel.slug` keeps the existing join serving only the
response projection.

Use case (`application/places/search.py`): add `category_id: int | None = None` and forward it
to `list_near`. Keep `DEFAULT_LIMIT` and `DEFAULT_RADIUS_METRES` untouched.

API (`api/v1/places.py`): add a `category` parameter declared as
`Annotated[str | None, Query(max_length=120, description="Category slug, see /api/v1/categories")] = None`,
and take a `CategoryRepo` dependency (already exported from `api/deps.py`; add it to the existing
import list). When `category` is set, resolve it with `await categories.get_by_slug(category)`;
if the result is None raise `HTTPException(status_code=422, detail="unknown category")` — the
same status an unknown `family` produces, so third parties get one failure mode for "filter
value does not exist". Pass `category_id=found.id` into `search_places`. Do not query the ORM
here: the endpoint keeps talking only to repositories.

Integration test (`tests/integration/test_places_search.py`): `_seed` must give one of the three
fixtures a category. Insert a category row and set `place.category_id` on
`test-search-gamma` ("Test Pharmacie Gamma") — the existing fixture inserts `place` rows with a
raw `INSERT`, so either add `category_id` to that statement for gamma or follow it with
`UPDATE place SET category_id = ...`. The category must NOT be attached to alpha or beta, and
must not change any distance, so `test_search_is_distance_sorted` and
`test_search_radius_bounds_the_results` keep their exact expected lists. Then add two tests:
`test_search_filters_on_category` asserts `_search(client, radius=5000, category=<slug>)`
returns only `["Test Pharmacie Gamma"]`; `test_search_rejects_unknown_category` asserts a
`category=does-not-exist` request returns 422. Extend `_cleanup` to delete the `categories` row
you add, or make its slug follow the existing `test-search-%` prefix so the existing
`DELETE FROM criteria WHERE slug LIKE 'test-search-%'` neighbour pattern can be mirrored.

Verify against the real database, not a mock: this endpoint's guarantee is the SQL predicate.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous client → `GET /api/v1/places` | `category` is untrusted free-form text arriving from the public internet on a rate-limited but unauthenticated endpoint |
| web BFF → API | the Next.js route handler forwards the browser query string verbatim; nothing validates it in between |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-01 | Tampering | `category` query parameter → `list_near` | medium | mitigate | The value is compared through a SQLAlchemy bound parameter (`PlaceModel.category_id == category_id`), never interpolated; it is bounded by `max_length=120`, and the parameter is resolved to an integer id before it reaches SQL. |
| T-10-02 | Denial of service | category predicate on a 634k-row `place` table | medium | mitigate | The predicate is a single indexed equality (`ix_place_category_id`) ANDed with the GiST radius predicate, so Postgres narrows on whichever is cheaper instead of scanning; the endpoint stays behind `public_rate_limit`. |
| T-10-03 | Information disclosure | 422 vs empty-200 on unknown slug | low | accept | The endpoint becomes an oracle for whether a category slug exists, but `/api/v1/categories` already publishes the full list anonymously, so nothing new is disclosed. |
| T-10-SC | Tampering | package installs | high | mitigate | No new dependency in this plan: FastAPI, SQLAlchemy, Next.js and pytest are already pinned; nothing to check against the package-legitimacy table. |
</threat_model>
