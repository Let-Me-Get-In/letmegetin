<objective>
Give every criterion and every accessibility filter at least one handicap family
(`moteur`, `auditif`, `visuel`, `mental`), from a reviewed data file, and keep it true
with an audit command — ticket LET-33, requirement DATA-01.

Purpose: `criteria.handicap_families` and `accessibility_filters.handicap_families` exist
since Phase 3 but are empty everywhere (the seed never sets them). Two features already
depend on them and are therefore dead today: the `family=` search filter
(`PlaceRepository.list_near`) and `get_place`'s per-family grouping. Without this plan the
referential is not trustworthy — a family filter matches nothing.

Planner decision recorded here because Phase 9 has no CONTEXT.md: the Acceslibre import is
**in scope as a capability, not as a national data load** (see 09-02). DATA-01 is independent
of places and is delivered here first, because it is the only DATA criterion that is
verifiable today with zero places and it unblocks a shipped search feature.

Output: `data/referential/families.csv`, the `families` use-case module, seed wiring,
`admin families sync|audit`, `criterion add --family`, tests.
</objective>

Implement `src/letmegetin/application/referential/families.py`:
- `load_families(path: Path) -> dict[str, list[str]]` — parse the CSV with `delimiter=";"`,
  validate each name with the same rule as `_validated_families` in
  `application/referential/admin.py` (raise `DomainError` on an unknown family, naming slug and
  value), order families by `HANDICAP_FAMILIES` order, ignore blank lines, raise `DomainError`
  on a duplicate slug.
- `apply_families(criteria: CriterionRepository, filters: MappingAdminRepository, assignments:
  dict[str, list[str]], *, overwrite: bool = False) -> FamiliesReport` where `FamiliesReport`
  counts `criteria_updated`, `filters_updated`, `inherited`, `unchanged`:
  1. load `criteria.list_all()` and the filter list; for each CSV slug, resolve it against
     criteria first then filters; a slug present in neither raises `DomainError` (a rename must
     fail loudly, never be skipped).
  2. write explicit rows with `criteria.update` / the mapping repository's filter update path
     (add `list_all()` and `update_families()` to the existing **`FilterRepository`** port (`MappingAdminRepository` is the category_mapping upsert port and has nothing to do with filters; `FilterRepository` today exposes only `list_active()`) only if no update path
     exists today — prefer adding a narrow `update_families(filter_id, families)` to the
     existing repository rather than a new repository class).
  3. options (`parent_id` set, no explicit row) inherit the parent's families; recurse parent
     first so nested options resolve.
  4. groups (a criterion that is a parent of other criteria) get the union of their direct
     children's families, in `HANDICAP_FAMILIES` order.
  5. with `overwrite=False`, only rows whose `handicap_families` is empty are written; with
     `overwrite=True`, every CSV row overwrites. Inheritance and group union always apply
     (they only fill empties).
- `audit_families(criteria: CriterionRepository, ...) -> list[str]` — return the slugs of
  criteria and filters whose `handicap_families` is empty, criteria first then filters,
  sorted; no writes.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo CSV → database | `data/referential/families.csv` is code-reviewed data; a typo silently changes which places a family filter returns |
| operator CLI → database | the only write path to the referential; no HTTP surface exists |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Tampering | `load_families` | medium | mitigate | Validate every family name against `HANDICAP_FAMILIES` and raise `DomainError` naming the slug; no free-form strings reach the ARRAY column |
| T-09-02 | Tampering | `apply_families` overwrite path | high | mitigate | Default `overwrite=False` fills only empty families; a bulk overwrite requires the explicit `--force` flag, so an operator's `criterion families` edit is never reverted by a routine sync |
| T-09-03 | Repudiation | family assignment provenance | low | accept | Assignment lives in git (`families.csv` diff + commit), which is a stronger audit trail than a new table for 75 static rows |
| T-09-SC | Tampering | package installs | high | mitigate | No new dependency: stdlib `csv` only; nothing to check against the package-legitimacy table |
</threat_model>
