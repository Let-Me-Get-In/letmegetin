    In docs/public-api.md:
    - Add the two rows to the endpoints table: `GET /export/latest.json` (current snapshot pointer) and
      `GET /export/{name}.zip` (an export ZIP), both under the anonymous quota.
    - Add an "ODbL export" section stating: the export is a ZIP of places.csv / categories.csv /
      criteria.csv / answers.csv / aliases.csv / ATTRIBUTION.txt / manifest.json; `latest.json` points to
      the current snapshot and available deltas; the files are generated on the host by the operator
      (never per request) and served read-only; and the manifest's `schema_version` announces the shape.
    - In the same section document the DELTA CONTRACT explicitly (D-10, moving watermark — NOT cumulative):
      `latest.json` carries `snapshot {name, seq}` (the last full snapshot and its consistent boundary) and
      `watermark` (the sequence up to which a delta has been published) as SEPARATE fields. A daily delta
      ZIP contains only the events with `seq > watermark - EXPORT_DELTA_OVERLAP` plus the merges in that
      window; the watermark advances only after the delta ZIP is fully written, so a failed run re-emits
      the same window. A partner applies the deltas in order over the snapshot. `--since <snapshot_seq>`
      is a CUMULATIVE catch-up for a partner who lost a delta. Never describe a delta as "cumulative
      since the snapshot".
    - In the same section document the CSV formula-injection guard RULE (F4): a leading `'` is prefixed
      only to the FREE-TEXT columns (places name/address_full/city/source_category; categories/criteria
      name) when the value starts with =, +, - or @; numeric/id/date/count/JSON columns (lat, lng, phone,
      postal_code, ids, dates, label, value) and the header row are NEVER guarded, so a negative longitude
      or +phone stays intact while a free-text formula is neutralised.
    - In the same section document what "origin id" means per file (matching the 14-02 wording): places ->
      the (source, source_id) pair; answers -> the (place_id, criterion_slug) natural key (answers have no
      source-side surrogate id); categories and criteria -> the slug. This is how EXP-01 ("each row
      carrying a stable id and its origin id") is honestly satisfied.
    - Add the Produced Works statement and the forward-looking sentence VERBATIM from the shared
      `application/places/attribution.py` constants (PRODUCED_WORKS_SENTENCE, FORWARD_LOOKING_SENTENCE) —
      do NOT retype them in the docs; copy the exact string so the docs and the ATTRIBUTION.txt generator
      read one shared constant. State that ATTRIBUTION.txt lists only the sources present in that ZIP,
      with legal names from data/referential/licences.csv. Do NOT document any OSM/Overture attribution
      line (D-05: there is none — upstream sources appear the day their rows do).
