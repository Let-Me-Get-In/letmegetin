<objective>
Wire the operator push: the outbound journal table, the owned-row stream, the read-then-diff use
case, the `acceslibre push` command, and the blocking read-only probe that resolves the identifier
question with a real key.

Purpose: PART-02 requires an operator to push our answers idempotently with conflict rules and
provenance strong enough that a later import cannot overwrite a fresher contribution. The inbound
side is already protected (`_rejection`); this plan ships the outbound side — the use case that GETs,
diffs, freshness-decides, PATCHes and journals — and the first real call (the probe) is a blocking
human checkpoint, because no API key exists (D-13).

Output: `acceslibre_push_write` model + migration `0014`, `push_repositories.py`, the `push_acceslibre`
use case, the `acceslibre push`/`acceslibre probe` CLI commands, and functional tests for dry-run,
idempotency and journaling.
</objective>
