<objective>
Build the outbound AccesLibre HTTP adapter (behind a domain port), the pure push-decision module,
and the read-only `acceslibre probe` command — then run the probe LIVE (blocking) to settle the
identifier question first.

Purpose: PART-02 needs an idempotent write-back to the AccesLibre REST API, and the research's
primary recommendation is to run a keyed, read-only probe that settles the identifier and the PATCH
payload shape BEFORE any write code is built on it. This plan builds the three foundations — the
typed adapter (incl. `list_erps`), the pure diff/freshness/validation decision, and the probe — and
ends on the blocking live probe, so the feed projection (15-03) and the push (15-04) consume a
verified identifier.

Output: `infrastructure/acceslibre/client.py`, `domain/places/acceslibre_push.py`, the
`acceslibre_api_key` setting, the httpx dependency move, the `acceslibre probe` command, and their
tests. The live probe resolves Open Question 1 (identifier) and confirms A1/A2.
</objective>
