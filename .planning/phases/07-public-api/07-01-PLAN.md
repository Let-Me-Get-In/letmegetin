# Phase 7 Plan — Public API & Deployment

**Ticket:** LET-12 · **Requirements:** API-01, API-02
**Depends on:** Phase 6 merged (web BFF, API client) and the existing `/api/v1`.

## Task 1 — API keys and the operator CLI

**Files**
- `domain/accounts/entities.py`: `ApiKey`.
- `domain/accounts/repositories.py`: `ApiKeyRepository` (`add`, `list_all`, `revoke`, `get_by_hash`).
- `infrastructure/persistence/models.py`: `ApiKeyModel`; migration `0007_api_keys.py`.
- `application/accounts/api_keys.py`: create (generate + hash + return the raw key once), list,
  revoke.
- `infrastructure/persistence/repositories.py`: SQLAlchemy adapter.
- `admin.py`: `api-key create|list|revoke` Typer group.

**Steps**
1. Migration: `api_key(id, label, key_hash unique, rpm default 60, active default true, created)`.
2. `secrets.token_urlsafe(32)` prefixed `lmg_`; `sha256` via `core.security.token_fingerprint`.
3. CLI prints the raw key **once**; `list` never shows it; `revoke` flips `active`.
4. Validation: `rpm` 1–10 000; unknown id → exit 1.
5. Tests: unit (format, hash, no raw in the list) + integration (create → list → revoke).

**Verify:** `uv run python -m letmegetin.admin api-key create --label test` prints a key; the DB
stores only the hash.

## Task 2 — Rate limiting and key authentication

**Files**
- `core/rate_limit.py`: fixed-window limiter (`check`, `reset`).
- `config.py`: `rate_limit_default_rpm=60`, `rate_limit_auth_rpm=10`, `rate_limit_window=60`.
- `api/deps.py`: optional `X-API-Key` via `APIKeyHeader`, `rate_limit` dependency.
- `api/v1/places.py`, `api/v1/referential.py`: router-level `Depends(rate_limit)`.
- `api/v1/auth.py`: router-level `Depends(auth_rate_limit)`.
- `web/src/app/api/[...path]/route.ts`: forward `X-API-Key` from `API_KEY` when set.

**Steps**
1. Limiter keyed by `key:<id>` or `ip:<client>`; fixed 60 s window.
2. Invalid key → 401; valid key → its `rpm`; anonymous → default.
3. Set `X-RateLimit-*` headers on success; on overflow `429` + `Retry-After`.
4. Auth router uses the stricter limit.
5. Tests: unit limiter (window reset), integration (headers, 429, invalid key 401).

**Verify:** after N calls the API returns 429 with `Retry-After`; a valid key gets its own budget.

## Task 3 — OpenAPI and public documentation

**Files**
- `main.py`: description, contact/licence, `openapi_tags`, `APIKeyHeader` security scheme.
- `scripts/export_openapi.py`: write `docs/openapi.json` from the app.
- `docs/public-api.md`: auth, limits, endpoints, errors, versioning, licence/attribution.
- `docs/openapi.json`: generated, committed.
- `.github/workflows/ci.yml`: `openapi` job regenerating and `git diff --exit-code`.

**Steps**
1. Tag the endpoints (`places`, `referential`, `auth`, `ops`) with descriptions.
2. Document `X-API-Key` and the 401/429 responses.
3. Generate `docs/openapi.json`; a test asserts the public paths and the security scheme.
4. README links to `docs/public-api.md`.

**Verify:** `/docs` and `/openapi.json` return 200; CI fails if the committed schema drifts.

## Task 4 — Deployable stack

**Files**
- `docker/Dockerfile` (multi-stage: `api`, `web`).
- `docker/entrypoint.sh` (migrate then serve).
- `docker-compose.prod.yml` (db + api + web, healthchecks, volumes).
- `web/next.config.ts`: `output: "standalone"`.
- `.github/workflows/ci.yml`: build both images (no push).
- `README.md` / `docs/deploy.md`: run instructions.

**Steps**
1. API image: `uv sync --frozen --no-dev`, copy `src/`, run `alembic upgrade head` then uvicorn.
2. Web image: `npm ci`, `npm run build`, run the standalone server on `:3000`.
3. Compose: PostGIS healthcheck; API waits for the DB; web waits for the API; env file.
4. Health: `/health` (API) and `/` (web) reachable locally.
5. CI builds both images.

**Verify:** `docker compose -f docker-compose.prod.yml up --build` → API `/health` 200, web `/` 200.

## Done when

1. A partner key authenticates, gets its own quota and sees the rate-limit headers; invalid keys
   and over-quota calls fail cleanly.
2. `/docs` and `/openapi.json` are published, documented and drift-checked.
3. The stack builds and runs locally from compose; the API migrations run on start.
4. 85 % coverage floor and CI (backend + web + images + OpenAPI) green.
