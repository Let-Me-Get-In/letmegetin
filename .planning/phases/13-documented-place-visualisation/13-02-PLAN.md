<objective>
Add the opt-in `with_documentation` signal to search. When the flag is set, each hit carries
`documentation: {rate, level}`, computed by a single batched read over the hit set (never N+1),
and the search card renders the level as text with a decorative border tint.

Purpose: this is the second vertical slice. It proves the batched rate query (the phase's one
unresolved design decision) and the additive opt-in contract (D-07, D-08).
Output: the search endpoint exposes `documentation` only under `with_documentation=true`, and the
search card shows the level.
</objective>

    forbids persistence).

    In src/letmegetin/domain/places/repositories.py add two ports:
    - PlaceRepository.list_accessibility_for_places(place_ids: Sequence[int]) -> dict[int, list[PlaceAccessibility]]
      returning the recorded values keyed by place id, for the given ids, in ONE query.
    - CategoryGridRepository.get_for_slugs(slugs: Sequence[str]) -> dict[str, CategoryGrid]
      returning the precomputed grid tree keyed by category slug, for the given slugs, in ONE query.
    These are the batched reads that replace any per-hit N+1.

    In src/letmegetin/infrastructure/persistence/repositories.py implement both:
    - list_accessibility_for_places: select PlaceAccessibilityModel joined to CriterionModel where
      place_id = ANY(:place_ids), ordered by CriterionModel.position, then group rows into
      dict[int, list[PlaceAccessibility]] in Python (reusing place_accessibility_from_models).
    - get_for_slugs: select CategoryModel.slug, CategoryGridModel.version, CategoryGridModel.tree
      joined on category_id where CategoryModel.slug = ANY(:slugs), returning
      dict[str, CategoryGrid] in Python.
    Use bound parameters (SQLAlchemy .in_ / bindparam), never string-interpolated IN lists. Do not
    add the documentation-level logic here — that stays in the domain ladder.
  </action>
