# Phase 13 — UI Design Contract

> Visual and interaction contract for PROD-01 (documented-place visualisation). Locked decisions
> D-01..D-11 come from `13-CONTEXT.md`. This file fixes what the decisions leave open: the palette
> per level, the legend layout, the empty-record banner, the family chips, and every accessible
> name. Generated by gsd-ui-researcher, verified by gsd-ui-checker, then revised after an
> `impeccable critique` pass on 2026-11-13 (see Open Questions, item 8).

**The rule this phase is built on:** the ladder is a statement about the data ("how well
documented"), never about the place ("how accessible"). The label's subject is always the record,
never the place. Colour never carries information alone. An empty record is never presented as a
low score of something.

## Documentation Ladder — Visual Tokens

The server owns the slugs and bounds (D-02). The web maps a slug to a token row below. It never
derives a level from a rate.

| Slug | Bounds (D-01) | Chip background (light) | Chip background (dark) | Chip text |
|------|---------------|-------------------------|------------------------|-----------|
| `none` | 0 % | none (transparent) | none (transparent) | muted |
| `sketch` | 1–25 % | `#dde4d9` | `#1d2c25` | ink |
| `partial` | 26–50 % | `#c3d4c5` | `#263b30` | ink |
| `good` | 51–75 % | `#a1bfab` | `#314e3f` | ink |
| `very_good` | 76–99 % | `#75a48b` | `#416854` | ink |
| `complete` | 100 % | `accent` `#1f6f4a` | `accent` `#7fd1a6` | paper |

Four tokens only: `--color-doc-sketch`, `--color-doc-partial`, `--color-doc-good`,
`--color-doc-very-good` (light in `@theme`, dark in the `prefers-color-scheme: dark` block, matching
the existing token pattern). `none` uses `line`/`muted` and `complete` uses the accent; declaring
`--color-doc-none` or `--color-doc-complete` would create a dead token.

Level → class mapping for chips:

| Slug | Chip classes |
|------|--------------|
| `none` | `border border-line text-muted` |
| `sketch` | `bg-doc-sketch text-ink` |
| `partial` | `bg-doc-partial text-ink` |
| `good` | `bg-doc-good text-ink` |
| `very_good` | `bg-doc-very-good text-ink` |
| `complete` | `bg-accent text-paper` |

Chips are `inline-flex items-center rounded-full px-3 py-1 text-sm font-semibold`. The chip is the
only colour surface: no card border tint (see Open Questions, item 8).

Search cards do not use the chip. They use a **marker**: `inline-flex items-center gap-2 text-sm
text-muted` with `span aria-hidden` `h-2.5 w-2.5 rounded-full` in the level's colour (`none` =
`border border-dashed border-muted`, `complete` = `bg-accent`, others `bg-doc-*`). The dot is
decorative; the name carries the fact. `levelDotClass(slug)` returns the dot's classes and
`levelChipClass(slug)` the chip's — two functions, two contexts, one source.

## Typography

The new elements use three sizes (Body 16, Label 14, Heading 20) and two weights. Three existing
styles in scope are kept unchanged and are not part of that set: the page title
(`text-3xl sm:text-4xl`, 30/36px), the search card's distance (`text-xs`, 12px), and the existing
body text around them.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 16px (`text-base`) | 400 | 1.5 | Banner body, legend intro, family labels, search card meta |
| Label | 14px (`text-sm`) | 600 | 1.4 | Level chips, legend terms, banner link |
| Heading | 20px (`text-xl`) | 600 | 1.4 (Tailwind default, no `leading-*` override) | Section headings, overall level (display face), banner title |
| Display | 36px (`text-4xl`) | 600 | existing class, unchanged | Page title (existing, unchanged) |

Weight 500 is not used. The overall level uses the display face at Heading size. Percentages use
`tabular-nums`.

**Hierarchy rule.** The level must outrank its own section title. `h2#completion` is rendered as a
small muted label — Body size, 400 weight, `text-muted` — not as a 20px heading. It stays an `h2`
for the accessibility tree (section name), while the eye lands on the `h3` level. The eyebrow
pattern from `DESIGN.md` is not used here: it is reserved for metadata and explicitly never a kicker
above a heading.

| Role | Value (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `paper` `#f7f4ec` / `#101613` | Page background |
| Secondary (30%) | card surface: `bg-white/60` (effective `#fcfbf7`) / `bg-white/5` (effective `#1c221f`) | Search cards, record panels, family figures |
| Accent (10%) | `accent` `#1f6f4a` / `#7fd1a6` | Reserved list below |
| Destructive | none | This phase has no destructive action |

Accent is reserved for:
- the progress bar fill (`accent`, on the `line` track);
- the `complete` chip background;
- the `sketch`–`very_good` chip backgrounds (the `doc-*` tokens are fixed tints of accent, not runtime alpha);
- the focus outline (existing `:focus-visible`);
- the existing primary buttons (unchanged).

Not accent: the banner link is ink text with an underline, and the banner uses the plain page
surface with a `line` border — not `accent-soft`, which already means "selected search card".

Warn (`#a3521f` / `#e0a07a`) is **not used** in this phase. Warn means "attention or problem", and
an undocumented place is not an error. Using it would imply the place is bad.

## Record Page — Completion Section (layout contract)

Order inside `<section aria-labelledby="completion">`:

1. `h2#completion` — "Complétude de la fiche" (existing key `completion`; kept, so the e2e text is unchanged).
2. `p` (muted, Body) — the legend intro, placed **above** the level: "La complétude mesure la part
   des critères renseignés. Elle ne dit pas si le lieu est accessible." It frames the level before
   the user reads it as a verdict.
3. `h3#doc-overall` — the overall level name in the display face at Heading size, e.g. "Fiche
   bien documentée".
4. `p` (muted, Body) — the existing `criteriaHaveValue` line, now the single place the percentage is
   printed: "62 % des critères ont une valeur." (no-break space before `%`; see Copywriting).
5. Progress bar:
   - `role="progressbar"`, `aria-valuenow` = percent (integer), `aria-valuemin=0`, `aria-valuemax=100`;
   - `aria-label` = "Complétude de la fiche" (existing `completion`);
   - `aria-valuetext` = "{level}, {percent} %" (fr) / "{level}, {percent}%" (en);
   - track `h-3 overflow-hidden rounded-full bg-line ring-1 ring-inset ring-muted`;
   - fill `h-full bg-accent`, width = percent;
   - no visible number inside the bar: the percentage is the sentence above it.
   The ring is added because `line` on `paper` is 1.26:1, below the 3:1 a non-text boundary needs.
6. Family `dl` (see Family chips), in `FAMILY_KEYS` order.
7. Legend (see Legend).

**Primary visual anchor:** the `h3` level name (`doc-overall`) — not the percentage and not the bar.
The level is the sentence a person reads first; the percent and the bar corroborate it.

### Family chips

Rendered with `FAMILY_KEYS` in this order: `moteur`, `auditif`, `visuel`, `mental`. Not
`Object.entries`, because the decisions log fixes the order.

Each family is a `div` in the existing `dl` (`rounded-card border border-line px-3 py-2`):

- `dt` — the family label (`familyLabel(family, locale)`), Body size, 400 weight, **ink** (not
  muted: the family is the subject of the row and must not be its quietest element);
- `dd` — the level chip only, no percentage. The percentage lives once, in the sentence above the bar.

Example in French: `Motricité` / `[Fiche bien documentée]`.

Chips carry no `aria-label`: the visible text is the accessible name, and the `dt` gives the
association. A family absent from `accessibility_by_family` shows the existing `notProvided` text
("Non renseigné") in the `dd`, with no chip, because a family with no criteria is not documented at
0 %.

Grid: `sm:grid-cols-2 lg:grid-cols-4` (existing).

## Legend (D-05, D-10)

Always visible, static, no tooltip, no `<details>`. Six entries, compact: one line each, no cards.

```
h3#doc-legend  — "Niveaux de documentation"
ul             — flex flex-wrap gap-x-3 gap-y-1, text-sm
  li (per level, ascending none → complete)
    span aria-hidden (swatch: h-3 w-3 rounded-full, the level's chip background;
                      `none` uses a dashed 1px `muted` border)
    " " + level name (600) + " " + bounds (400, muted)
```

- Bounds render `{min}–{max} %` in fr (no-break space before `%`), `{min}–{max}%` in en. `none`
  shows `0 %`, `complete` `100 %`.
- Six entries wrap onto two or three lines at 375px instead of six bordered boxes; nothing is
  truncated and no meaning text is repeated (see Open Questions, item 8).
- The intro sentence that used to sit here moved above the level heading (see the completion
  section), so the legend is a key, not a preamble to the accessibility tree.
- Bounds come from the server ladder (Open Questions, item 2). The web does not hard-code them.

## Empty Record (D-06)

When the overall level is `none`, the banner **is** the completion section: no separate `h2`, `h3`,
percent line, bar or family grid. A zero-width bar and four "Non renseigné" cards state nothing the
banner does not.

```
section#doc-undocumented aria-labelledby="doc-undocumented-title"
  classes: rounded-card border border-line p-4 space-y-2
  h2#doc-undocumented-title  — "Cette fiche n'est pas encore documentée"   (Heading)
  p                          — body copy (Body, muted)
  a href="#contribute"       — "Ajouter une information" (new key `docBannerCta`;
                               underline, underline-offset-4, 600 weight)
```

- Placed directly after the page header and after `VerifyBanner` (the blocking notice).
- The section is static. It is not `role="status"`: the banner is there on page load, and announcing
  it live would be noise.
- The link targets the existing contribution section (`id="contribute"`); its focus style is the
  global 3 px accent outline.
- The legend stays visible below the banner: it explains the ladder the user is about to help fill.
- With no tree (`noTree`), the banner still shows. When `noTree` also applies, the banner link is
  **not** rendered: a place with no criteria grid has nothing to complete, so the action would be a
  dead end. The `noTree` message carries the explanation.

## Search Result Card

Card markup stays the `Link` in `place-list.tsx`. Its inner rows, top to bottom:

1. Name and distance (existing).
2. Category and address (existing, muted).
3. Row `flex flex-wrap items-center gap-2 mt-2`:
   - the level **marker**: a 10px dot in the level's colour plus the level name in Label size,
     `text-muted`, **no pill fill and no border**. It must not share the geometry of the
     operating-status pill (a `warn` pill in the same row), or a green "Fiche complète" and an
     amber "Doublon possible" read as sibling statuses of equal weight;
   - the operating-status or duplicate pill (existing, when not `open`).

The chip renders only when `documentation` is in the response. If the field is missing (older API,
or the flag is off), no chip renders and the card looks as it does today. There is no border tint:
selection and hover already own the border colour, and in dark mode four of the six tints are
indistinguishable on `#101613` (Open Questions, item 8).

**Primary visual anchor:** the place **name** (existing link text). The chip is the second thing
read and carries the documentation signal as text.

## Data Contract the UI Depends On

The UI renders what the server provides. It never derives a level from a rate (D-02).

| Consumer | Needs | Status today |
|----------|-------|--------------|
| Search results (`GET /api/v1/places?with_documentation=true`) | `documentation: { rate, percent, level }` per result; absent by default (D-07) | Not built |
| Record detail (`GET /api/v1/places/{slug}`) | overall `documentation: { rate, percent, level }` | Not built; `filled_rate` exists |
| Record detail | a level for each of the four families, keyed by family, on the same denominator as the overall rate | Not built; `accessibility_by_family` carries rates only |
| Legend bounds | the six slug → bounds table | Served by the server ladder (Open Questions, item 2) |
| Search request (web) | `placesPath` adds `with_documentation=true` | Web change; update `placesPath` and its test |

**Rounding rule.** The server computes `percent = floor(rate * 100 + 0.5)` and derives `level` from
that integer against the published bounds, in one place, and **sends `percent` in the payload**. The
web prints `documentation.percent` verbatim and never re-rounds (`page.tsx` stops calling
`Math.round(filled_rate * 100)`). Without `percent` in the payload the guarantee is unenforceable.

**Denominator (measured defect, fixed in this phase).** `filled_rate` currently divides by the grid
nodes that are not `array` and not `option`, which drops all 55 option criteria and leaves **2**
leaves: the rate can only be 0, 0.5 or 1, and `sketch`, `good` and `very_good` can never occur.
The denominator becomes the grid's **answerable** criteria — everything except `array` groups and
except option nodes whose parent is also an option. On category 1 that is 19 criteria, so the 8
fields AccesLibre populates score 8/19 = 42 %. Expect most imported places to sit in the lower
bands: that is the honest reading of the data, not a regression.
The same denominator, filtered by handicap family, is used for the family rates; a family with no
grid leaf is **absent** from `accessibility_by_family` (today it is reported as 0.0, which reads as
"not documented" for every place outside the family). All 8 populated AccesLibre criteria are
`moteur`, so `visuel`, `auditif` and `mental` will legitimately be absent until contributions
exist — the "Non renseigné" branch is the correct display, not a bug.

**Unknown slug.** If a level slug is not in the web's map, the chip and the level heading are
omitted and the percent sentence remains: an unknown enum must not break the page, and must not be
labelled with a guess.

**Caching.** `with_documentation` is part of the response, so it must be part of any cache key
(`ETag`/`Vary`); otherwise a client that did not ask for the field receives it, or a client that
did receives a response without it.

Without family levels the family chips cannot be rendered per D-04, and the phase is blocked.
