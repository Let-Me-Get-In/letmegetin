# Phase 13 — UI Design Contract

> Visual and interaction contract for PROD-01 (documented-place visualisation). Locked decisions
> D-01..D-11 come from `13-CONTEXT.md` and are not re-opened here. This file fixes what the
> decisions leave open: the palette per level, the tint alpha on the search card, the legend
> layout, the empty-record banner, the family chips, and every accessible name. Generated by
> gsd-ui-researcher. Verified by gsd-ui-checker.

**The rule this phase is built on:** the ladder is a statement about the data ("how well
documented"), never about the place ("how accessible"). Colour never carries information alone.
An empty record is never presented as a low score of something.

and an undocumented place is not an error. Using it would imply the place is bad.

## Record Page — Completion Section (layout contract)

Order inside `<section aria-labelledby="completion">`:

1. `h2#completion` — "Complétude de la fiche" (existing key `completion`; kept, so the e2e text is unchanged).
2. `h3` — the overall level name in the display face at Heading size (for example "Bien documenté").
   Its `id` is `doc-overall`.
3. `p` (muted, Body) — the existing `criteriaHaveValue` line ("62% des critères ont une valeur.").
4. Progress bar (below):
   - `role="progressbar"`, `aria-valuenow` = percent (integer), `aria-valuemin=0`, `aria-valuemax=100`;
   - `aria-label` = "Complétude de la fiche" (existing `completion`);
   - `aria-valuetext` = "{level}, {percent} %" (fr, D-10) or "{level}, {percent}%" (en);
   - track `h-3 overflow-hidden rounded-full bg-line ring-1 ring-inset ring-muted`;
   - fill `h-full bg-accent`, width = percent.
   The ring is added because `line` on `paper` is 1.26:1, below the 3:1 a non-text boundary
   needs. The bar extent is also in the text, so this is a recommended fix, not a required one.
5. Family `dl` (see Family chips), in `FAMILY_KEYS` order.
6. Legend section (see Legend).

When `filled_rate` is `0`, the overall level is `none`: the fill has zero width, the value text
reads "Non documenté, 0%", and the banner appears above the section.

**Primary visual anchor:** the `h3` level name (`doc-overall`) — not the percentage and not the
bar. The level is the sentence a person reads first, the number and the bar corroborate it. On the
empty record the anchor is the banner heading, which stands above the completion section.

### Family chips

Rendered with `FAMILY_KEYS` in this order: `moteur`, `auditif`, `visuel`, `mental`. Not
`Object.entries`, because the decisions log fixes the order.

Each family is a `div` in the existing `dl` (`rounded-card border border-line px-3 py-2`):

- `dt` — the family label (`familyLabel(family, locale)`), Body size, 400 weight, muted;
- `dd` — the level chip (Label size) followed by the percentage (`{N}%`, Base size, 600 weight, `tabular-nums`).

Example in French: `Motricité` / `[Bien documenté]  62%`.

Chips carry no `aria-label`: the visible text is the accessible name, and the `dt` gives the
association. A family absent from `accessibility_by_family` shows the existing `notProvided` text
("Non renseigné") in the `dd`, with no chip, because a family with no criteria is not
documented at 0%.

Grid: `sm:grid-cols-2 lg:grid-cols-4` (existing).

## Legend (D-05, D-10)

Always visible, static, no tooltip, no `<details>`.

```
section aria-labelledby="doc-legend"
  h3#doc-legend  — "Niveaux de documentation"
  p (muted)      — legend intro
  dl             — grid gap-3, one column < 640px, two at sm, three at lg
    div (per level, ascending none → complete)
      rounded-card border border-line px-4 py-3
      dt — swatch (aria-hidden, h-3 w-3 rounded-full, the level's chip background; `none` uses a line border) + level name + bounds
      dd — one-line meaning (Body, muted)
```

- The `dt` holds the name and bounds on one line (Label size, 600 weight); bounds are muted, 400 weight.
- Six entries, in order from `none` to `complete`. Six in three columns gives two rows, so the top row shows the low levels.
- The `dl` is not given its own name: the `h3` provides it through the section's `aria-labelledby`.
- Bounds are rendered `{min}–{max} %` in fr (no-break space before `%`), `{min}–{max}%` in en.
  The `none` level shows `0 %`, the `complete` level `100 %`.

Bounds source: see Open Questions, item 2. The web does not hard-code the bounds without a parity test.

## Empty-Record Banner (D-06)

Rendered when the overall level is `none`. Placed directly after the page header and after the
`VerifyBanner` (which is the blocking notice), and before the completion section.

```
section aria-labelledby="doc-undocumented"
  classes: rounded-card border border-line bg-accent-soft/40 p-4
  h2#doc-undocumented   — "Cette fiche n'est pas encore documentée"   (Heading)
  p                     — body copy (Body, muted)
  a href="#contribute"  — "Compléter cette fiche" (existing key `completeThisRecord`; underline, underline-offset-4, 600 weight)
```

- The section is static. It is not `role="status"`: the banner is there on page load, and announcing it live would be noise.
- The link targets the existing contribution section (`id="contribute"`). Its focus style is the global 3px accent outline.
- The banner does not appear on a populated record, and it never uses warn.
- With no tree (`noTree`), the banner still shows, and the accessibility section keeps its existing `noTree` message. See Open Questions, item 6.

## Search Result Card

Card markup stays the `Link` in `place-list.tsx`. Its inner rows, top to bottom:

1. Name and distance (existing).
2. Category and address (existing, muted).
3. Row `flex flex-wrap items-center gap-2 mt-2`:
   - the level chip (Label size, text = level name only, no percentage);
   - the operating-status or duplicate pill (existing, when not `open`).

The level chip is rendered only when `documentation` is in the response. If the field is missing
(older API, or the flag is off), no chip and no tint render, and the card looks as it does today.

### Border tint and selection precedence

- Default border: the level's border tint (table above); `none` keeps `border-line`.
- Hover: the existing `hover:border-accent` wins over the tint while the pointer is on the card.
  The level text stays.
- Selected (`place.slug === selected`): `border-accent bg-accent-soft/50` wins over the tint.
  Selection is the stronger signal, and the level text stays on the card.

A `complete` card and a selected card share the accent border; they are told apart by the selected
card's `bg-accent-soft/50` fill and by the level text.

Card is `rounded-card border p-4` (existing). The tint is a 1px border colour change; no
thickness change, so the card does not shift.

**Primary visual anchor:** the place **name** (existing `h3`/link text). The level chip is the
second thing read and the tint is the third; neither competes with the name, and the tint carries no
meaning on its own.

## Accessibility Contract

Accessible names and roles, per element:

| Element | Role / structure | Accessible name | Value / state |
|---------|------------------|-----------------|---------------|
| Completion section | `section` + `h2` | "Complétude de la fiche" | — |
| Overall level | `h3` | its text, e.g. "Bien documenté" | — |
| Progress bar | `role="progressbar"` | "Complétude de la fiche" (`aria-label`) | `aria-valuenow` = N; `aria-valuetext` = "{level}, N %" |
| Family chip | `dd` text | the `dt` family name + the `dd` text, e.g. "Motricité: Bien documenté 62%" | — |
| Legend | `section` + `h3` | "Niveaux de documentation" | — |
| Legend entry | `dt` / `dd` pairs | the `dt` text (name + bounds) and the `dd` meaning | — |
| Swatch (legend, chip) | decorative | none (`aria-hidden`) | — |
| Empty-record banner | `section` + `h2` | "Cette fiche n'est pas encore documentée" | — |
| Banner link | `a` | "Compléter cette fiche" | target `#contribute` |
| Search card | `a` (existing link) | its text includes the level name, e.g. "Café … Bien documenté" | — |

Notes:
- The level name is text in every position: the progress bar, the chips, the legend, the card, and the banner heading. Colour is never the only carrier.
- The progress bar's `aria-valuetext` gives the level and percent together, so a screen reader gets both without reading the bar's visual fill.
- The search card's link name includes the level, so screen-reader users hear the documentation signal on the result, not only on the record.
- No `aria-live` region is added. Level changes come from a contribution, which already announces through the form's own status.
- Focus order is unchanged. No new interactive control is added except the banner link, which is the first focusable element after the header's existing links in the record view.

### Motion

No new motion. The existing `prefers-reduced-motion` rule covers the card and chip transitions (`transition-colors` already on the card).
