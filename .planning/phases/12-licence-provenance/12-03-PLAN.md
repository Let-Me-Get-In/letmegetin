<objective>
Turn the licence catalogue into a reviewed, auditable data surface with an operator CLI: the
`admin licences sync|matrix|audit` group mirrors the existing `families` commands, loading all three
reviewed CSVs (`licences.csv`, `licence_destinations.csv`, `source_licences.csv`), so adding or
changing a destination or a source → licence mapping is a git-reviewed CSV change, never a code
change (LIC-05). This plan completes D-05/D-06/D-07/D-08 beyond 12-01's schema and backfill, and
loads the runtime tables the write path (12-02) and predicate (12-04) read.

Purpose: make licence rules a data review — the phase's core promise (LIC-05) — with an exit-1 audit
gate so a gap or an unknown licence cannot slip through, and with a DDD-clean repository boundary so
the application layer never touches the ORM directly.

Output: `licences.py` loaders + sync/audit/matrix use cases, the `LicenceRepository` port +
`SqlAlchemyLicenceRepository` implementation, the `admin licences` typer group, seed integration, and
unit + functional tests mirroring the families lineage.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Reviewed CSV → `licence`/`licence_destination`/`source_licence` tables | A git-reviewed data file is the source of truth; an erroneous row would silently widen or narrow the redistribution rule or the source → licence mapping. |
| Operator CLI → DB | Trusted operator, but `destination`/`licence_slug`/`source` strings from the CSV must stay in a closed set. |
