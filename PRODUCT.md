# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Primary: people with disabilities, their relatives and carers, looking for a place they can actually enter and use — quickly, on a phone, before going there.
Secondary: developers and partner organisations who want to consume the open accessibility referential through the public API.

## Product Purpose

LetMeGetIn tells anyone in seconds whether a place is truly accessible, through a structured accessibility record that any site or app can consume. The product is both a public search app and an open referential behind a public API.

## Positioning

A normalised accessibility referential (place categories, typed hierarchical criteria, official labels) exposed as an open API, seeded from open data and completed by contributions. It is not a review site with an accessibility filter; the record itself is the product, and third parties can build on it.

## Operating Context

- The app lives at `app.letmegetin.org`; the apex `letmegetin.org` is reserved for this public landing page.
- Visitors arrive from brand search, a shared place record, a partner site, or the open-data/developer community.
- French is the reference language; the interface and the landing are bilingual fr/en.
- Accessibility is a product requirement, not a marketing claim: keyboard, screen readers, contrast, reduced motion.

## Capabilities and Constraints

- Search places by proximity, text, category and accessibility criteria.
- Read a structured accessibility record with completion rate, photos and reviews.
- Contribute values and publish reviews with an account.
- Consume the same data through the public API (`https://api.letmegetin.org/docs`).
- Data comes from Acceslibre (Etalab 2.0), OpenStreetMap (ODbL) and Overture, plus contributions.
- The code is public: `https://github.com/Let-Me-Get-In/letmegetin`.
- Public contact: `contact@letmegetin.org`.
- No invented traction, customer names, benchmarks or partnerships.

## Brand Commitments

- Name: LetMeGetIn; wordmark set in Literata with the final "In" in the accent green.
- Existing app world: warm paper ground, deep ink, a single green accent, generous type, calm density.
- Tone: direct, useful, never charitable or pitying; the person is competent, the place is the problem.
- Primary action on the landing: search a place. Secondary action: use the API.

## Evidence on Hand

- About 635,000 places in the national Acceslibre import (measured 2026-11-06: 634,931).
- Public API documentation at `https://api.letmegetin.org/docs`.
- Public source repository at `https://github.com/Let-Me-Get-In/letmegetin`.
- Verifiable source licences: Acceslibre (Etalab 2.0), OpenStreetMap (ODbL), Overture.
- No testimonials, press coverage, user counts or partner logos are available; do not fabricate them.

## Product Principles

1. Answer the real question — can I get in? — before selling anything.
2. Show the structure: a record, not an opinion.
3. Keep the data open and the code inspectable.
4. Design for the people the web usually excludes.
5. Never overclaim what the data knows.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Keyboard-complete, screen-reader tested, visible focus, sufficient contrast, reduced-motion respected. The audience includes people using zoom, voice control and screen readers.
